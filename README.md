# Fibrinolysis in STEMI When Timely Primary PCI Is Not Available: Tenecteplase versus Alteplase

An interactive, referenced walkthrough of the decision algorithm for
fibrinolytic agent selection and weight/age-based dosing in ST-segment
elevation myocardial infarction (STEMI), for the large proportion of
patients worldwide who cannot receive timely primary PCI. Every box and
decision point in the diagram can be selected to reveal, in one place:
what the step means, why the algorithm calls for it, the exact dosing as
authored, and the sources behind it.

**Live site:** https://satbuhan.github.io/tenecteplase-alteplase-stemi-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why*,
and a reader outside the authors' own team cannot easily check the
evidence behind a specific box (why tenecteplase over alteplase at all;
why half-dose at 75; why routine angiography still matters after
successful fibrinolysis). This page keeps the original algorithm exactly
as authored, and attaches the clinical reasoning and literature to each
box without cluttering the diagram itself.

The algorithm this page presents is Figure 2 of "Tenecteplase versus
Alteplase for Fibrinolysis in ST-Segment Elevation Myocardial Infarction:
A Systematic Review of Two Decades of Evidence with Risk-of-Bias, GRADE
and Clinical-Significance Appraisal" — the review's own "practical
decision algorithm that integrates [its] findings with current guideline
recommendations" (Section 4.2).

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Every one of the manuscript's 103 references was independently
  re-verified** against a primary source (DOI/PMID resolution, plus a
  title/author/journal/subject-matter check) rather than trusted from the
  manuscript's own reference list — no citation-verification exception was
  given for this build. One correction was found: **reference 45**
  (Zia-Behbahani et al., *Iranian Journal of Pharmaceutical Research*,
  2019) lists its second author as "Hossein, H." in the manuscript; the
  actual author is **Niknahad, H.** — "Hossein" was the author's first
  name, mistaken for a surname. Title, journal, DOI and pagination are
  otherwise correct; `assets/content.js` carries the corrected name.
- **Ten references (12–21) could not be independently verified for this
  build** — not because anything was found wrong with them, but because
  this session's web-search tool budget was exhausted partway through
  verification (five parallel passes were run to cover all 103 references
  at once, and the budget is shared across all of them) and did not
  refresh before the build needed to proceed. This is an honest, flagged
  tooling limitation, not a finding about the papers: each of the ten is
  marked `"Not independently verified this build — session search budget
  exhausted; verify before relying on it clinically"` in its own `kind`
  field in `assets/content.js`, rather than silently presented as
  checked. **Two of the ten — reference 19 (Zhao et al. 2023, the
  largest direct randomised comparison) and reference 20 (Bainey et al.
  2024, the pooled STREAM-1/2 analysis for patients aged ≥75) — are
  directly cited on flowchart nodes** (`start_fibrinolysis`,
  `full_dose_tenecteplase`, `age_75`, `half_dose_tenecteplase`), so this
  is worth closing out rather than leaving open: a follow-up build pass,
  once the search budget resets, should re-run verification on refs
  12–21 specifically and update their `kind` fields.
- The diagram's trunk, its two side-branch terminals, the age-based dosing
  fork, and the closing reassessment fork were transcribed directly from
  the authors' own Figure 2 image (inspected directly, not just
  text-extracted) and cross-checked against the manuscript's own Section
  1 (eligibility/timing), Table 2 (pharmacology/dosing), Section 3.8
  (age-adjusted dosing) and Section 3.10 (adjunctive therapy). Given this
  is a 103-reference systematic review behind a 13-box algorithm — not
  every reference maps onto a specific box; many support background
  epidemiology, review methodology, or cross-indication evidence. The
  full, independently-verified reference list is always in the References
  panel regardless of which refs a given node cites.

## Disclaimer

This is an academic / educational reference tool, not a substitute for
institutional protocol or bedside clinical judgement. Verify any dose or
timing against current local protocol before clinical use.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site
that GitHub Pages can serve directly.

```
index.html          page structure — masthead, the diagram (trunk, two
                     sideways terminals, the age-based dosing fork, the
                     closing reassessment fork), readout panel,
                     references, abbreviation legend, footer
assets/style.css     design (the "paper" masthead/references, the
                     single-trunk diagram grid and its 2-wide fan-outs)
assets/content.js     ← single source of truth for every node's text,
                     dosing, and reference list. Edit this file to change
                     what the page says.
assets/app.js         rendering + interaction (builds the diagram and its
                     connector lines from content.js, handles the
                     click-to-expand panel on desktop and the bottom
                     sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box or decision
diamond from the diagram (`meaning`, `rationale`, optional `dose` table,
and `refs` pointing at numbered entries in `REFERENCES`). Add or edit a
reference in `REFERENCES` and point to it by `id` from any node. Never
change a node's `label` or `sub` text without the author team's sign-off —
those fields are the algorithm itself, transcribed verbatim from Figure 2.
